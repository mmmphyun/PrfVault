## 3. 재현·통과 확인 4가지 (평가 기준 충족)

1. **어디서 확인하나요**:
   - 제출한 실행 묶음 `submission/T12-BRB-Submission/PrfVault-Web-Playground.zip`의 압축을 새 임시 폴더에 풀고, 브라우저에서 `index.html`을 더블클릭합니다. (별도 Node.js, 웹서버, 계정 로그인, 인터넷 연결 일체 불필요).
2. **무엇을 하나요 (3단계 이내)**:
   - **1단계**: 상단 빠른 선택 칩에서 `[네이버 (16자 제한)]`을 클릭하여 1단계 진단 카드에서 최대 길이 16자 및 엔트로피 결손율(-20.0%)을 확인합니다.
   - **2단계**: 2단계 카드의 `[적응형 고엔트로피 암호 생성]` 버튼을 클릭하여 16자리 암호 생성과 NIST SP 800-63B 권고치($131.09\text{ bits}$) 대비 엔트로피 바 차트 및 GPU 크랙 예상 시간 비교 수치를 확인합니다.
   - **3단계**: 빠른 선택 칩에서 `[삼성증권 (키패드)]`를 선택한 뒤 3단계 카드의 `[1회용 마스킹 복사 & 5초 Zeroize 시작]`을 클릭합니다. Wasm 선형 메모리 헥스 덤프에서 5초 후 평문 바이트가 `0x00`으로 덮어씌워지는 상태 변화(`Active` $\rightarrow$ `Zeroized`)를 확인하고 하단 가상 로그인 폼에 붙여넣어 제출합니다.
3. **무엇이 보이면 통과**:
   - 첫 화면 최상단에 논문 전체 제목과 위 "앱 한 문장"이 분명하게 고정되어 있습니다.
   - 1단계 진단 영역에 `네이버 (naver.com) 비표준 제약: -20.0% 결손 (104.87 bits)` 경고 배지가 출력됩니다.
   - 2단계 비교 그래프에 NIST 권고치($131.09\text{ bits}$)와 네이버 허용치($104.87\text{ bits}$)의 엔트로피 막대 그래프가 대비되어 표시됩니다.
   - 3단계 Wasm 헥스 덤프 뷰어의 상태 태그가 `Wasm Memory Active`에서 5초 카운트다운 후 `Zeroized (0x00 완전 소거됨)`으로 바뀌며 바이트가 모두 `00 00 00 ...`으로 갱신됩니다.
4. **안 될 때**:
   - 브라우저의 클립보드 권한 차단 환경인 경우 `[즉시 Wasm 물리 소거(Zeroize)]` 버튼을 누르면 즉시 메모리가 0x00으로 소거되어 헥스 덤프가 갱신됩니다.

## 4. AI와 내 판단 3줄 (평가 기준 충족)

- **AI에게 맡긴 일**: 국내 50대 웹사이트 실측 데이터셋(`scripts/results/benchmark-analysis.json`)의 자바스크립트 모듈 변환, NIST SP 800-63B 수식 기반 섀넌 엔트로피 및 GPU 크랙 소요 시간 계산 엔진 바인딩, Rust WebAssembly Base64 인라인 번들러 및 임시 폴더 무결성 검증 패키징 스크립트 작성.
- **내가 판단한 일**: 단순 계정 생성/로그인 화면 데모를 넘어 논문의 핵심 실측 결과(네이버/KT 16자 제한 20% 엔트로피 결손, 금융권 가상 키패드 차단율 6.7%)를 처음 온 평가자가 1분 안에 직접 체감할 수 있도록 '도메인 제약 진단 $\rightarrow$ 적응형 KDF 암호 생성 및 엔트로피 비교 $\rightarrow$ 1회용 마스킹 복사 및 5초 Wasm Zeroize 헥스 덤프 시연' 3단계 구조로 애플리케이션의 핵심 흐름을 확정함.
- **AI 말을 안 들은 일**: AI가 제안한 대형 프레임워크 기반의 Node.js/Vite 번들링 구조는 임시 폴더에서 즉시 실행 시 `npm install`이나 로컬 개발 서버를 요구해 평가자의 실행 편의를 해치고 실패 리스크를 높일 수 있으므로 이를 거부하고, 외부 종속성이 0건인 순수 단일 HTML5/ES 모듈/Wasm 인라인 번들 방식으로 단축 단순화함.
